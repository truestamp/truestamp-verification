# The agent-sufficiency test, 2026-09-30

**The test passes.** All twelve sessions, two per base fixture, passed every run of their
fixture exactly (SPEC.md 7.4, Passing): 1,516 runs, 758 in each round. No session failed,
so there is nothing to diagnose, and the constructions text stands unchanged.

  `c0d70826d7501d5089184d1947bad3dcc33c3172269d425f16fc0025ed07df49`.

- **The agent:** Claude Code 2.1.280 in headless mode (`claude -p`) with the prompt's exact

  - The tools were Bash, Read, Edit and Write only, with `--permission-mode dontAsk`.
  - `--safe-mode`, `--disable-slash-commands`, `--setting-sources ''` and
    `--strict-mcp-config` with no servers loaded nothing of the operator's: no project
    instructions, memory, skills, plugins or MCP servers.
- **The place:** each session had its own Docker Sandbox (`sbx` 0.46.0, local), built by
  `sandbox/agent-test.sbxenv.yaml`.
  - The image is pinned by digest:
    `docker.io/docker/sandbox-templates:claude-code-docker@sha256:549730947ed8a43182547bb5628245fe6d6c089564dd73d2194e899f791d970f`.
  - The session's directory held only `PROMPT.md` and the fixture's files, outside any
    repository.
  - The network reached only `api.anthropic.com` and `platform.claude.com`, checked for
    each sandbox before the session started.
  - The login was a Claude subscription, with no API key.
- **Python:** 3.14.4, with `cryptography` 50.0.2 and `rfc8785` 0.1.4 installed from
  hash-pinned wheels (`sandbox/kits/agent-test/`).

## Information only: two sessions on Claude Sonnet 5.5

The same setup and harness, on Claude Sonnet 5.5 (`claude-sonnet-5-5`), to see how a smaller
model does. These sessions are not part of the test, so their outcome revises nothing.

| Fixture | Passed | Runs | Time | Turns | Tool calls | Output tokens |
|---|---|---|---|---|---|---|
| 1-item | no | 90 of 91 | 194 s | 6 | 5 | 27,852 |
| 4-entropy | yes | 233 of 233 | 289 s | 8 | 7 | 40,312 |

1-item's one failing run is `item.witness_names`, a broken version whose item record leaves
`entropy_nist` out of `witness_hashes` while the proof still carries that witness.
- **The rule held.** The session's script caught it, printing both edges as `none`.
- **One extra line.** It also printed a value at
  `/proof/subject/record/witness_hashes/entropy_nist`, a member the proof does not have. The
  prompt asks for a line for each member of the proof whose value the text computes, so a
  member that is absent gets none.
- **The diagnosis:** the model misread the prompt's line rule, not the constructions text.
  Both Opus 5.5 sessions on this fixture printed no such line.
